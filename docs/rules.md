# Rules

This page lists every rule id and what the rule rejects. How the rules apply
inside macro bodies is described in [Known limits](limits.md#macro-bodies).

Rule ids appear in findings, baseline entries and canary marks. "Workspace"
means the Cargo workspace being checked. Paths resolve through `use` trees,
renames, aliases and re-exports; `core`/`alloc` count as `std`. Method and macro
rules match by name, not type.

| `struct-rest-pattern`       | a `..` in a struct, tuple-struct or enum-variant pattern whose type is declared in the workspace (`let`, `let else`, `match`, `if let`, `while let`, `for`, closure and fn parameters, `matches!`, macro bodies): `Config { a, .. }`, `Wrapper(a, ..)`, `Event::Move { x, .. }`. A `..` that `catch-all-arm` reports in a `match` belongs to `catch-all-arm`, and the `..` of an enum-variant pattern that `refutable-shortcut` reports (`if let Ws::A { .. } = x`, `while let`, `let else`, `matches!`) belongs to `refutable-shortcut`: neither is reported a second time. | `default-construction`      | `#[derive(Default)]` (also inside `cfg_attr`) on a struct or union declared in the workspace, any number of fields, generics included, reported at the `Default` ident; and struct-update syntax whose base is a `default()` call (`Account { balance, ..Default::default() }`, `..Account::default()`, `..<Account as Default>::default()`) on a workspace struct, reported at the `..`. A derived `Default` fills every field with a blank value that may be invalid for the domain, and the update form hides which fields were chosen. A hand-written `impl Default` is not flagged, so `T::default()` and `Default::default()` calls elsewhere are not flagged (once the derive is banned, every workspace `Default` is hand-written; external types are outside this rule). An enum may derive `Default`: Rust requires an explicit `#[default]` variant, so a variant was chosen on purpose. Struct update from any other base (`..old`, `..old.clone()`) and from an external or unresolved struct is not flagged                                                          |
| `unused-underscore-binding` | a `let` that binds an `_`-prefixed name (`let _x = ..`, `let _x: T = ..`, `let Some(_x) = .. else {..}`, `_x` inside tuple, struct and slice patterns) that nothing later in the enclosing block mentions. Bare `_` is `discarded-value`. Any later occurrence of the identifier counts as a read (closures, nested blocks, macro tokens, inline format arguments such as `"{_x}"`, a shadowing `let`), so a use that might be a read is not reported. No name is exempt, `_guard` included: `drop(_guard)` later in the block is a read. Fn and closure parameters and `match`, `if let` and `for` patterns are not covered                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `dropped-call-result`       | `drop(..)`, `std::mem::drop(..)`, `core::mem::drop(..)` (through `use` and aliases) whose argument is directly a call, method call, macro call or `?` expression: the value just produced is thrown away. `drop(guard)` of a named binding, a field or a reference is legal                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `swallowed-error`           | a `match` arm `Err(_)`, `Err(..)` or `Err(_name)` (also `Result::Err`, `std::result::Result::Err`) with an empty body, `()` or `{ () }`, and `if let Ok(..) = ..` or `while let Ok(..) = ..` with no `else`, also when the `let` is an operand of an `&&` let chain (`if let Ok(v) = f() && ready`). A `_` that `catch-all-arm` reports, and an `Ok(..)` pattern that names a workspace variant (`refutable-shortcut` reports those), are not reported a second time                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

| `ambient-input`             | `std::env`, `fs`, `os`, `process`, `net`, `thread`, `time`, stdio, print/`dbg!`/`env!` macros, and file-system probes through `Path` (`Path::exists`, `is_file`, `is_dir`, `metadata`, `read_dir`, `canonicalize`, `try_exists`, `symlink_metadata`, `read_link`, `is_symlink`; `PathBuf` too), except in a `shell` member's listed `ambient` entries. In method form `canonicalize`, `read_dir`, `try_exists`, `symlink_metadata`, `read_link` and `is_symlink` are flagged by name; `exists`, `metadata`, `is_file` and `is_dir` only on a receiver that is visibly `Path::new(..)`, `PathBuf::new()` or `PathBuf::from(..)`, optionally chained through `join`, `parent`, `as_path`, `to_path_buf`, `with_extension` or `with_file_name` (the receiver's type is not known, so `let p = ..; p.exists()` is not seen)                                                                                                                                                                                                                         |

`preference-omission` is a note, not a finding. Every run prints one for each
lint omitted as a preference (see
[Lint coverage and canaries](lint-coverage.md)) and does not change the exit
code.

Per-rule detail is in `src/rules.rs` and the canaries. Configuration keys are
defined in `src/config.rs`; the parser rejects unknown keys (exit 2). This
repository's own `.unrepresentable/config` is a working example.
